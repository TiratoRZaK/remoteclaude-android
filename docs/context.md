# Контекст проекта remoteclaude-android

Точка входа для новой сессии: что это, какие решения приняты и почему, как проверять и
выпускать. Спека — `specs/2026-08-13-android-client-spec.md`, план — `plans/2026-08-13-android-client-plan.md`.

## Что это

Нативный Android-клиент к личному серверу **remoteclaude** (`W:\Person\remoteclaude`,
Node 22): с телефона видно живые сессии Claude Code, ленту диалога и терминал, можно
писать промпты и жать управляющие клавиши. Протокол сервера не менялся ни разу — клиент
говорит ровно то же, что веб-страница из `public/app.js`.

- Локально: `W:\Person\remoteclaude-android`, git с авторством
  `Ruslan Abdrakhmanov <vip.ra.19992@gmail.com>`.
- GitHub: `https://github.com/TiratoRZaK/remoteclaude-android` (публичный, ветка `main`).
- Ссылка на свежий APK: `releases/latest/download/app-debug.apk`.
- Токен сервера лежит у пользователя в `%USERPROFILE%\.rclaude\config.json`, в коде и
  документации его быть не должно.

## Слои

| Модуль | Содержимое |
|--------|-----------|
| `:protocol` | чистая JVM: `ConnectionLink` (разбор ссылки), `Messages`/`ProtocolJson` (кадры), `TerminalKeys` (последовательности), `UrlCoding`, `ReconnectPolicy`, `net/` (OkHttp HTTP+WS, `SessionConnection` с реконнектом), `term/` (эмулятор терминала, UTF-8-декодер) |
| `:app` | Compose Material 3: экраны `connect`, `sessions`, `session`, `settings`; ViewModel + StateFlow; DataStore; `ui/theme` (оформления, скины терминала); `ui/session` (лента, терминал, панель клавиш) |

Зависимость односторонняя: `:app` знает про `:protocol`. Юнит-тесты живут в `:protocol`
(и немного в `:app` — метаданные оформлений, дельта ввода) и гоняются на JVM без эмулятора.

## Принятые решения

- **Размер PTY клиент не меняет.** Кнопка «Под экран» слала `resize` и ломала отображение
  во вкладке терминала на компьютере — владелец размера именно она. Вместо этого лупа:
  локальный кегль 0.5–5× плюс горизонтальная прокрутка полотна. `ClientMessage.Resize`
  оставлен в протоколе как часть контракта, но не отправляется.
- **Панель клавиш постоянная**, в обоих видах, над системной клавиатурой. Первая клавиша
  переключает вид и работает индикатором: значок терминала пульсирует по `menuWaiting`,
  значок чата помечается точкой при новых репликах. Вкладки и плашка «Claude ждёт ответа»
  за ненадобностью убраны.
- **Два режима композера.** «Пакет» — bracketed paste с Enter (многострочный промпт
  целиком). «Живой» — символы уходят в PTY по мере набора, поэтому работают меню
  слэш-команд и подсказки по `@`; буквы даёт системная клавиатура, свою раскладку не
  делаем (русский с автозаменой и свайпом важнее).
- **Оформлений семь**, каждое меняет шрифты, палитру, скругления, фон и раскраску
  терминала; выбор в настройках, хранится в DataStore. Шрифты вшиты (OFL, см. `FONTS.md`),
  все с кириллицей — проверял покрытие cmap через fontTools.
- **Версии AndroidX подобраны под compileSdk 36** (Compose BOM 2026.05.00, lifecycle
  2.10.0, core-ktx 1.18.0): более новые требуют AGP 9.1 и SDK 37, которых в локальном SDK
  нет (и cmdline-tools для доустановки тоже нет).
- **Никаких JDK-API новее API 26 в `:protocol`.** Android-lint чистую JVM-часть не
  проверяет, поэтому там только `URI`, `IOException`, `ByteArrayOutputStream`, `TimeUnit`,
  а процентное кодирование своё (`UrlCoding`).

## Грабли, стоившие времени

- **`URLEncoder/URLDecoder(String, Charset)` — только с API 33.** На телефоне пользователя
  (Android 12 или старше) приложение падало при сканировании QR и при открытии сессии.
  Эмулятор API 37 этого не воспроизводил, lint не видел `:protocol`. Отсюда правило выше.
- **Автопрокрутка ленты и терминала** сначала снималась приходом новых данных: длинный
  буфер прилетал, `pinned` становился `false` раньше, чем срабатывал скролл, и терминал
  показывал пустое начало. Правильно — снимать признак по завершении жеста
  (`isScrollInProgress` + `canScrollForward`).
- **Роли Material 3 надо задавать все.** Незаданные `surfaceContainer*` остаются
  сиреневыми из базовой палитры и лезут в карточки — поэтому `buildScheme` выводит их
  подмешиванием от `panel`.
- **Compose держит минимум 48dp на кликабельный элемент.** Плотная панель клавиш
  получается только с `LocalMinimumInteractiveComponentSize`, иначе ряды не влезают.
- **Слэш-команда требует двух Enter:** первый принимает подсказку автодополнения, второй
  выполняет. Это поведение Claude Code, не баг клиента.
- **Git Bash ломает аргументы вида `/help`** в `adb shell input text` (превращает в путь) —
  нужен префикс `MSYS_NO_PATHCONV=1`.
- **Эмулятор при холодном старте терял установленное приложение и его данные**, а Play
  Store иногда перехватывал тапы — при автоматизации это выглядит как «приложение
  вылетело».

## Как проверять

JVM-тесты: `./gradlew test` (сейчас 94, падений нет), плюс `./gradlew :app:lintDebug`.

Живая проверка против настоящего сервера на эмуляторе:

```bash
SDK=$USERPROFILE/AppData/Local/Android/Sdk
"$SDK/emulator/emulator.exe" -avd Small_Phone -no-boot-anim -no-snapshot-save &
"$SDK/platform-tools/adb.exe" install -r app/build/outputs/apk/debug/app-debug.apk
"$SDK/platform-tools/adb.exe" reverse tcp:7777 tcp:7777   # адрес сервера тогда http://127.0.0.1:7777
```

Дальше `adb shell input tap/text`, а координаты элементов брать не на глаз, а из
`adb exec-out uiautomator dump /dev/tty` (у Compose-элементов есть `text`/`content-desc`).
Клавиатуру закрывать `input keyevent 111` (ESCAPE): `keyevent 4` (BACK) выходит из
приложения. Скриншоты — `adb exec-out screencap -p > файл.png`.

Для опытов с вводом заводить одноразовую сессию, а не трогать рабочую:

```bash
curl -X POST -H "Authorization: Bearer <токен>" -H "Content-Type: application/json" \
  --data-binary '{"cwd":"<временный каталог>","args":[],"cols":80,"rows":24}' \
  http://127.0.0.1:7777/api/sessions
```

Закрывать её отправкой Ctrl+C и двух Ctrl+D в `/ws` (через маленький node-скрипт с `ws`
из `W:\Person\remoteclaude\node_modules`) — `/exit` не сработает, если в строке ввода
остался текст.

## Выпуск версии

1. Поднять `versionCode` и `versionName` в `app/build.gradle.kts`.
2. `git commit`, затем `git tag vX.Y.Z && git push origin main --tags`.
3. Экшен `.github/workflows/release.yml` сверяет `versionName` с тегом (иначе падает),
   прогоняет тесты, собирает APK и прикладывает его к релизу под именем `app-debug.apk`,
   чтобы ссылка `releases/latest/download/app-debug.apk` продолжала работать.

Сборка отладочная, подписана debug-ключом: для домашней установки достаточно, в Play
такое публиковать нельзя. Latest определяется датой публикации релиза, поэтому номера
тегов должны только расти.

## Что за рамками

- Создание и завершение сессий из приложения — это делает `rclaude` на компьютере.
- Полный VT220: мышь, графика, двойная ширина, ответы на запросы состояния.
- Своя буквенная раскладка (обсуждалась, отклонена в пользу системной клавиатуры).
- Жест «щипок» для лупы: сейчас только кнопки, чтобы не конфликтовать с прокруткой списка.
- Работа через интернет: обсуждали Tailscale или ZeroTier как транспорт (кода не требует,
  у Radmin VPN нет Android-клиента). Если делать «по-взрослому» — токен в заголовке
  WebSocket вместо query, запрет открытого HTTP для публичных адресов через network
  security config, токены на устройство с отзывом, урезанное проигрывание буфера при
  переподключении.
- Подписанный release-APK и публикация в сторе.
