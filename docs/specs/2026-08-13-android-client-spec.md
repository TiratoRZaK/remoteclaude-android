# remoteclaude-android — спека нативного клиента

Дата: 2026-08-13. Базовые документы (репозиторий `remoteclaude`):
`docs/superpowers/specs/2026-08-13-remoteclaude-design.md` (протокол — контракт) и
`docs/superpowers/specs/2026-08-13-remoteclaude-chat-design.md` (чат-вид).
Эталон поведения — веб-клиент `public/app.js`.

## Цель

Нативный Android-клиент к личному серверу remoteclaude в локальной сети: список живых
сессий Claude Code, чтение ленты диалога, ввод промптов и управление терминалом с
телефона. Протокол не меняется — клиент говорит ровно то же, что веб-страница.

## Границы

- Только клиент. Создание сессий (`POST /api/sessions`) в UI не выводится: сессию
  заводит `rclaude` на компьютере.
- Терминал — читающая реализация, не полноценный VT220: рендерятся текст, ANSI-цвета,
  позиционирование курсора и очистка. Мышь, sixel, двойная ширина не поддерживаются.
- Без TLS-специфики: сервер в LAN отдаёт HTTP, приложение разрешает cleartext.
- Один сервер за раз (адрес + токен в DataStore).

## Экраны

### Подключение

Поле ссылки вида `http://192.168.1.40:7777/#t=<токен>`, кнопка сканирования QR
(ZXing), поле токена (заполняется из ссылки, правится вручную), кнопка «Проверить» →
`GET /api/health` с показом версии сервера, кнопка «Сохранить и продолжить».
Адрес и токен хранятся в DataStore Preferences; при старте приложение открывает список
сессий, если адрес уже сохранён.

### Список сессий

`GET /api/sessions` → карточки: имя, cwd, число зрителей, метка «чат», геометрия
`cols×rows`. Pull-to-refresh, автообновление при возврате на экран. Пустой список и
401 — понятные сообщения. Кнопка перехода к настройкам подключения.

### Сессия

Один WebSocket на экран, две вкладки поверх общего потока.

- **Чат.** Лента `chat`-событий: пузыри пользователя справа, Claude слева, вызовы
  инструментов — компактной строкой «Имя · деталь». Автопрокрутка вниз, пока лента
  прижата к низу; иначе кнопка «↓ вниз». Заметка о ненайденном транскрипте по
  `chat.unavailable`, снимается при появлении событий.
- **Терминал.** Экранный буфер эмулятора со скроллбэком, моноширинный шрифт. На
  единичном увеличении кегль подобран так, чтобы вся ширина сессии влезала в экран;
  лупа в шапке меняет кегль в пределах 0.5–5× и включает горизонтальную прокрутку
  полотна. Размер PTY клиентом не меняется: им владеет вкладка терминала на
  компьютере. Панель быстрых клавиш (Esc, ⇧Tab, стрелки, Enter, Ctrl+C, Clear, 1–5).
- Композер общий для вкладок: многострочное поле, отправка bracketed paste
  (`[200~` + текст + `[201~` + `\r`).
- Статусная плашка соединения: подключение, потеря связи с обратным отсчётом паузы,
  завершение сессии с кодом, ошибка от сервера.

## Слои

```
:protocol (Kotlin JVM, без Android)          :app (Android, Compose)
├── ConnectionLink   разбор ссылки/токена     ├── data/SettingsRepository (DataStore)
├── Messages/ProtocolJson  разбор кадров      ├── ui/connect, ui/sessions, ui/session
├── TerminalKeys     escape-последователь.    ├── ViewModel + StateFlow
├── ReconnectPolicy  нарастающая пауза        └── AppContainer (ручной DI)
├── net/RemoteClaudeApi   OkHttp HTTP
├── net/SessionSocket     OkHttp WebSocket
├── net/SessionConnection реконнект-цикл, Flow<SessionEvent>
└── term/TerminalEmulator ANSI/UTF-8 → сетка ячеек
```

`:protocol` не зависит от Android SDK: его юнит-тесты гоняются обычным `test` на JVM.
UI знает про `:protocol`, обратной зависимости нет.

## Протокол в типах

- `ServerMessage`: `Chat(reset, unavailable, events)`, `Status(menuWaiting)`,
  `Exit(code)`, `Error(message)`, `Unknown(type)`. Разбор ручной по полю `type`:
  битый JSON и незнакомые поля не роняют разбор, а дают `null`/`Unknown`.
- `ChatEvent`: `kind` ∈ {user, assistant, tool}, `text`, `name`, `detail`, `ts`.
  Событие с незнакомым `kind` или без полезной нагрузки отбрасывается, остальные
  события кадра сохраняются.
- `ClientMessage`: `Input(data)`, `Resize(cols, rows)` — сериализация kotlinx.
  `Resize` описан контрактом, но клиент его не шлёт: размер PTY принадлежит вкладке
  терминала на компьютере.
- Бинарный кадр — сырые байты PTY, уходят в эмулятор.

## Соединение

`SessionConnection` держит цикл: открыть сокет → отдавать события → при закрытии,
если пользователь не ушёл, ждать паузу из `ReconnectPolicy` (1 с, ×2, потолок 15 с) и
открывать заново. Успешное открытие сбрасывает паузу; перед проигрыванием буфера
эмулятор очищается, лента заменяется `reset`-кадром. `exit` завершает цикл без
переподключения.

## Эмулятор терминала

Инкрементальный UTF-8-декодер (склейка многобайтовых символов на границе кадров) →
конечный автомат ANSI (GROUND/ESC/CSI/OSC/строковые) → экран `cols×rows` из ячеек
(символ + стиль) и скроллбэк готовых строк (до 1500).

Поддержано: CUU/CUD/CUF/CUB, CNL/CPL, CHA, CUP/HVP, VPA, ED (0/1/2/3), EL (0/1/2),
IL/DL, ICH/DCH/ECH, SU/SD, DECSTBM, SGR (сброс, жирный, тусклый, курсив, подчёркивание,
инверсия, 16 цветов, 256 цветов, truecolor), сохранение/восстановление курсора,
alt-screen (1047/1049), autowrap с отложенным переносом, табуляция, RI/NEL/IND, RIS,
OSC и прочие строковые последовательности — проглатываются.

Снимок экрана — список строк из стилевых прогонов; UI перерисовывается по снимку не
чаще раза в 60 мс.

## Тесты

JVM-юниты в `:protocol`: разбор ссылки (схемы, порт по умолчанию, токен во фрагменте и
в query, процентное декодирование, ошибки), разбор серверных кадров и чат-событий,
сериализация клиентских, escape-последовательности панели и bracketed paste,
`ReconnectPolicy` (рост, потолок, сброс), эмулятор (текст, перенос, цвета, очистки,
позиционирование, скроллбэк, alt-screen, разрезанный UTF-8 и разрезанный CSI),
`SessionConnection` на поддельном сокете (реконнект, сброс паузы, остановка по exit).
